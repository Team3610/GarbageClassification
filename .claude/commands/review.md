# 코드 리뷰

현재 브랜치에서 변경된 파일들을 리뷰한다.

## 실행 절차

1. `git diff develop...HEAD --name-only`로 변경 파일 목록 확인
2. `git diff develop...HEAD`로 전체 변경 내용 확인
3. 변경된 파일을 직접 읽어 맥락 파악

## 리뷰 기준

### AI/모델 코드 (`AI/`)
- 학습/검증/테스트 데이터셋이 올바르게 분리되는지
- 전처리(정규화, 리사이즈 등)가 학습·추론 양쪽에 동일하게 적용되는지
- Stage 1 → Stage 2 파이프라인 흐름이 명확한지
- 앙상블 다수결 투표 로직이 올바른지 (동점 처리 포함)
- ONNX 변환 시 입출력 shape, dynamic axis 설정이 적절한지
- 하드코딩된 경로나 매직 넘버가 없는지

### 프론트엔드 코드 (`Frontend/`)
- ONNX Runtime Web 세션 생성 및 입력 텐서 shape이 모델과 일치하는지
- 이미지 전처리(리사이즈, 정규화)가 학습 시와 동일한지
- 추론 결과 후처리(softmax, argmax, 레이블 매핑)가 정확한지
- XSS 등 보안 취약점이 없는지
- 사용자 피드백(로딩 상태, 에러 메시지)이 적절히 처리되는지

### 공통
- CLAUDE.md의 커밋 태그 규칙(`feat:`, `fix:` 등)을 따르는지
- 불필요한 주석이나 디버그 코드(`print`, `console.log`)가 남아 있지 않은지
- 함수/변수명이 역할을 명확히 드러내는지

## 출력 형식

```
## 리뷰 대상
- 브랜치: <현재 브랜치명>
- 변경 파일: <목록>

## 문제 (반드시 수정)
- [파일명:줄번호] 문제 설명 및 수정 방법

## 제안 (권장)
- [파일명:줄번호] 개선 제안

## 확인 사항
- [파일명:줄번호] 의도를 확인해야 할 부분

## 요약
전체적인 평가 (1~2문장)
```

문제가 없으면 "문제 없음" 으로 표기한다.
